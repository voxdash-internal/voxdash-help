title: "Question Metadata"

The **Question Metadata** panel allows you to configure the technical and statistical properties of an individual question. These settings determine how the question is represented in exported datasets, particularly when the questionnaire is exported to statistical software such as **SPSS**.

Question metadata does **not** change how a question is displayed to respondents or how they interact with it. Instead, it defines how the collected responses are stored, formatted, labeled, and interpreted during data analysis.

Metadata is especially useful for researchers, data analysts, and organizations that require standardized datasets. Proper configuration helps ensure that exported data has consistent **variable types, measurement levels, numeric formats, variable labels, and missing-value definitions**.

> **Tip:** In most cases, you can keep the default metadata generated by VoxDash. Modify these settings when your research methodology, reporting standards, or organization's data dictionary requires specific formatting.

## Accessing Question Metadata

To open the **Question Metadata** panel:

1. Open the questionnaire in the **Editor Panel**.
2. Select the question you want to configure.
3. Open the **Question Metadata** section in the right-side panel.
4. Review or modify the available metadata settings.
5. Save the questionnaire to apply your changes.

The available metadata options can vary depending on the selected **question type**.

## Label Preparation

The **Label Preparation** section controls how the selected question is identified and documented in the exported dataset.

Clear labels are particularly important when analyzing an SPSS file containing many variables. A descriptive variable label allows analysts to understand what a variable represents without having to return to the original questionnaire.

### Question Full Text

**Question Full Text** displays the complete text of the survey question.

The full question text is useful as a reference when preparing variable labels, reviewing the questionnaire structure, or generating documentation.

**Example:**

Question shown to respondents:

> **How satisfied are you with your recent online shopping experience?**

The Question Full Text field contains the complete question text.

### Variable Label

The **Variable Label** is the descriptive label assigned to the variable in the exported dataset.

Unlike a variable name, which is generally short and system-oriented, a variable label should be descriptive enough for an analyst to understand the purpose of the variable.

**Example:**

| Question                                                           | Variable Label        |
| ------------------------------------------------------------------ | --------------------- |
| How satisfied are you with your recent online shopping experience? | Customer Satisfaction |

In SPSS, the variable may appear as:

```text
Variable Name : Q5
Variable Label: Customer Satisfaction
```

#### Best Practice

Use labels that are:

* Clear and descriptive
* Consistent across questionnaires
* Easy for analysts to understand
* Short enough to comply with the export format's limitations

For example, **Customer Satisfaction** is generally more useful than an ambiguous label such as **Question 5**.

## Bytes Counter

The **Bytes Counter** displays the number of bytes currently used by the **Variable Label**.

This counter helps you monitor the length of the label and avoid exceeding the supported limit of the export format.

**Example:**

Variable Label:

```text
Customer Satisfaction
```

Bytes Counter:

```text
21 / 255 bytes
```

> **Note:** The byte count can differ from the number of visible characters when the label contains characters that require more than one byte to encode.

## Advanced SPSS Settings

The **Advanced SPSS Settings** section controls how the selected question is represented and stored in SPSS.

These settings are primarily intended for users who need control over statistical data formatting. Most users can keep the default values unless their organization has specific requirements.

Available settings may include:

* Read Only
* Numeric Width
* Numeric Decimals
* Numeric Format
* String Width

### Read Only

**Read Only** prevents accidental changes to the SPSS metadata configuration.

When enabled, the relevant metadata settings cannot be modified until **Read Only** is disabled.

**Example:**

If **Read Only** is enabled:

1. An administrator or authorized user has configured the SPSS settings.
2. Other users can view the settings.
3. The settings cannot be edited.
4. Disabling **Read Only** allows the configuration to be modified again.

This can be useful when standardized metadata must be protected from accidental changes.

### Numeric Width

**Numeric Width** specifies the maximum number of digits that can be stored for a numeric value.

**Default:** `10`

**Example:**

Question:

> **How many products did you purchase?**

Possible response:

```text
125
```

With a numeric width of `10`, the field is configured to accommodate numeric values within the specified width.

> **Note:** Numeric width defines the storage/display format; it does not necessarily define the business validation range of the question. Use the question's validation settings to control what respondents are allowed to enter.

### Numeric Decimals

**Numeric Decimals** specifies the number of decimal places used for numeric values.

**Default:** `0`

**Example:**

Question:

> **How many hours did you shop online?**

| Stored Value | Decimals |
| -----------: | -------: |
|            5 |        0 |
|          5.5 |        1 |
|         5.75 |        2 |

If **Numeric Decimals** is set to `2`, the SPSS format can represent values with two decimal places.

### Numeric Format

**Numeric Format** determines how numeric values are formatted in SPSS.

**Default:** `F` (Fixed Numeric)

**Example:**

| Value | SPSS Format |
| ----: | ----------- |
|    25 | F10.0       |
| 82.35 | F10.2       |

The format works together with **Numeric Width** and **Numeric Decimals**.

For example:

```text
F10.2
```

means a fixed numeric format with a width of 10 and 2 decimal places.

### String Width

**String Width** defines the maximum number of characters allocated for a string/text variable in the exported dataset.

**Default:** `255`

**Example:**

Question:

> **Please describe your shopping experience.**

If the string width is `255`, the exported field is configured to accommodate up to 255 characters.

String width is particularly relevant for questions such as:

* Long Text
* Text inputs
* Email
* URL
* Barcode
* Other text-based question types

> **Tip:** Choose a width that accommodates the expected response while avoiding unnecessarily large fields when your organization's data standards require tighter definitions.

## SPSS Format

The **SPSS Format** section summarizes the formatting configuration applied to the selected question.

Depending on the question's data type, the available information may include:

* **Format**
* **Width**
* **Decimals**
* **Configuration Level**
* **Admin Defaults**

**Example:**

| Setting             | Value          |
| ------------------- | -------------- |
| Format              | F              |
| Width               | 10             |
| Decimals            | 0              |
| Configuration Level | Admin Defaults |

### Configuration Level

The **Configuration Level** indicates where the current metadata configuration originates.

If an administrator has established default SPSS settings, those settings can be automatically applied to questions unless they are overridden by a question-specific configuration.

This allows organizations to maintain consistent formatting across questionnaires while still supporting exceptions when necessary.

## Missing & Special Values

Respondents cannot always provide a valid answer to every question. For example, a respondent may:

* Not know the answer
* Refuse to answer
* Not be eligible for the question
* Consider the question not applicable

Instead of leaving these responses blank, you can assign predefined **Missing & Special Values**.

These values allow exported datasets to distinguish between different reasons why a valid response is unavailable.

Common examples include:

* **Don't Know**
* **Refused to Answer**
* **Not Applicable**

When configured appropriately, these codes can be recognized by SPSS as missing values rather than valid observations.

### Add a Missing Value

To add a missing value:

1. Click **+ Add Missing Value**.
2. Enter the **Code**.
3. Enter the **Label**.
4. Select the appropriate **Configuration Level**.
5. Save the configuration.

**Example:**

Question:

> **What is your annual household income?**

You could configure:

| Code | Label             |
| ---: | ----------------- |
|   97 | Not Applicable    |
|   98 | Don't Know        |
|   99 | Refused to Answer |

The resulting dataset could contain:

| Respondent | Stored Value |
| ---------- | -----------: |
| John       |        65000 |
| Sarah      |           98 |
| David      |           99 |

> **Important:** Choose missing-value codes that cannot be confused with legitimate responses. For example, if `99` could be a valid response to a particular question, use a different code.

### Reset Missing Values

Click **Reset Missing Values** to restore the administrator's default missing-value definitions.

Use this option when:

* You have customized the missing values for a question.
* You want to discard question-specific changes.
* You want to return to the organization's standard definitions.

For example, if your organization uses `97`, `98`, and `99` consistently for special responses, resetting the configuration restores those administrator-defined values.

## Data Type Information

The **Data Type Information** section displays how the selected question is represented in the exported dataset.

The two key properties are:

* **Measurement Level**
* **Data Type**

These properties are important because statistical software uses them to determine how variables should be interpreted during analysis.

### Measurement Level

**Measurement Level** defines the statistical level of the question.

Common measurement levels are:

* **Nominal**
* **Ordinal**
* **Scale**

#### Nominal

Nominal variables represent categories without a meaningful order.

Examples:

* Gender
* Country
* Customer type
* Product category

#### Ordinal

Ordinal variables represent categories with a meaningful order, but the distance between categories is not necessarily equal.

Examples:

* Satisfaction from 1–5
* Agreement scales
* Ranking questions
* Star ratings

#### Scale

Scale variables represent numeric measurements where mathematical operations are meaningful.

Examples:

* Age
* Revenue
* Number of purchases
* Numeric scores
* Slider values

**Example:**

| Question           | Measurement Level |
| ------------------ | ----------------- |
| Gender             | Nominal           |
| Satisfaction (1–5) | Ordinal           |
| Age                | Scale             |

### Data Type

**Data Type** defines the underlying type of value stored for the question.

Common data types include:

* **Numeric**
* **String**
* **Date**
* **DateTime**
* **Time**

**Example:**

| Question      | Data Type |
| ------------- | --------- |
| Age           | Numeric   |
| Customer Name | String    |
| Purchase Date | Date      |

The data type determines how the value is represented in the exported dataset and affects how statistical software can process it.

## SPSS Metadata Based on Question Type

VoxDash automatically determines much of the SPSS metadata based on the **question type** and, where applicable, its specific configuration.

This means that two questions that look similar in the questionnaire can have different SPSS representations depending on their underlying input type.

For example, a numeric input such as **Number** is exported as a numeric scale variable, while a **Text** input is exported as a string variable.

> **Important:** The question type determines the default metadata. Question-specific settings, administrator defaults, and export rules can further affect the final configuration.

The following table summarizes the default SPSS metadata for supported question types.

### Choice and Rating Questions

| Question Type          | SPSS Format | Data Type | Measurement Level | Governing Rule                      |
| ---------------------- | ----------- | --------- | ----------------- | ----------------------------------- |
| Radio Button Group     | F10.0       | Numeric   | NOMINAL           | Measurement §4                      |
| Dropdown               | F10.0       | Numeric   | NOMINAL           | Measurement §4                      |
| Checkboxes             | F10.0       | Numeric   | NOMINAL           | Measurement §4                      |
| Multi-Select Dropdown  | F10.0       | Numeric   | NOMINAL           | Measurement §4                      |
| Yes/No (Boolean)       | F10.0       | Numeric   | NOMINAL           | Measurement §4                      |
| Image Picker           | F10.0       | Numeric   | NOMINAL           | Measurement §4 · Format admin table |
| Ranking                | F10.0       | Numeric   | ORDINAL           | Measurement §4                      |
| Rating Scale — Labels  | F10.0       | Numeric   | ORDINAL           | Measurement §4                      |
| Rating Scale — Stars   | F10.0       | Numeric   | ORDINAL           | Measurement §4                      |
| Rating Scale — Smileys | F10.0       | Numeric   | ORDINAL           | Measurement §4                      |

#### How to interpret these settings

Most choice-based questions are stored as **numeric variables** in SPSS. The numeric values represent the selected options, while the **Nominal** or **Ordinal** measurement level determines how those values should be interpreted statistically.

For example:

* A **Radio Button Group** is generally **Nominal** because its categories do not inherently have an order.
* A **Rating Scale** is **Ordinal** because the response categories have an ordered relationship.
* A **Ranking** question is **Ordinal** because rank positions have a meaningful order.

### Single-Line Input Questions

Single-Line Input questions support multiple HTML input variants. Their SPSS metadata depends on the selected **input type**.

| Input Type    | SPSS Format | Data Type | Measurement Level | Governing Rule                      |
| ------------- | ----------- | --------- | ----------------- | ----------------------------------- |
| No input type | A255        | String    | NOMINAL           | Measurement §5 "otherwise"          |
| Text          | A255        | String    | NOMINAL           | Measurement §5                      |
| Color         | A255        | String    | NOMINAL           | Measurement §9 note                 |
| Email         | A255        | String    | NOMINAL           | Measurement §9 note                 |
| Password      | A255        | String    | NOMINAL           | Measurement §5                      |
| Phone Number  | A255        | String    | NOMINAL           | Measurement §9 note                 |
| URL           | A255        | String    | NOMINAL           | Measurement §9 note                 |
| Number        | F10.0       | Numeric   | SCALE             | Measurement §5 · Format admin table |
| Range         | F10.0       | Numeric   | SCALE             | Measurement §5                      |
| Date          | DATE11      | Date      | SCALE             | Date/Time §8 · Master Rec W 11      |
| Date and Time | DATETIME20  | DateTime  | SCALE             | Date/Time §8                        |
| Time          | TIME8       | Time      | SCALE             | Date/Time §8                        |
| Month         | A255        | String    | SCALE             | Held                                |
| Week          | A255        | String    | SCALE             | Held                                |

#### Why the input type matters

A **Single-Line Input** is not a single SPSS data type. Its underlying `inputType` determines how the response is stored.

For example:

```text
Text      → A255 → String
Number    → F10.0 → Numeric
Date      → DATE11 → Date
DateTime  → DATETIME20 → DateTime
```

Therefore, when configuring metadata or reviewing an export, always consider both the **question type** and the **input type**.

> **Note:** Some input types, such as Month and Week, are currently represented as strings while retaining a Scale measurement level according to the current metadata rules.

### Text and Capture Questions

Text and capture questions generally store respondent-provided content as string variables.

| Question Type | SPSS Format | Data Type | Measurement Level | Governing Rule |
| ------------- | ----------- | --------- | ----------------- | -------------- |
| Long Text     | A255        | String    | NOMINAL           | Measurement §4 |
| File Upload   | A255        | String    | NOMINAL           | Measurement §4 |
| Signature     | A255        | String    | NOMINAL           | Measurement §4 |

#### Long Text

**Long Text** responses are stored as strings rather than numeric values because respondents can enter free-form text.

#### File Upload

For **File Upload**, the exported value is represented as a string. The value can be used to identify or reference the uploaded file according to the application's export behavior.

#### Signature

**Signature** is also represented as a string variable in the metadata model.

> **Note:** String-based metadata describes how the exported value is represented. It does not necessarily mean that the original uploaded content itself is embedded directly inside the SPSS dataset.

### Container and Non-Exported Question Types

Some questionnaire elements are designed to organize or structure other questions rather than collect an independent response.

These elements do **not** create a standalone SPSS variable.

| Question Type        | SPSS Format | Data Type | Measurement / Export Rule |
| -------------------- | ----------- | --------- | ------------------------- |
| Panel                | —           | —         | NOT EXPORTED              |
| Dynamic Panel        | —           | —         | Container                 |
| Single-Select Matrix | —           | —         | Per-cell metadata         |
| Multi-Select Matrix  | —           | —         | Per-column metadata       |
| Dynamic Matrix       | —           | —         | Per-column metadata       |
| Multiple Textboxes   | —           | —         | Per-sub-item metadata     |
| HTML                 | —           | —         | NOT EXPORTED              |
| Image                | —           | —         | NOT EXPORTED              |
| Expression           | —           | —         | NOT EXPORTED              |

#### Panel and Dynamic Panel

A **Panel** or **Dynamic Panel** acts as a container for other questionnaire elements. Because the container itself does not represent an independent respondent variable, it does not create a standalone SPSS variable.

#### Matrix Questions

Matrix questions require special handling because the matrix itself is a container for multiple response items.

For example:

* **Single-Select Matrix** → metadata is applied **per cell**.
* **Multi-Select Matrix** → metadata is applied **per column**.
* **Dynamic Matrix** → metadata is applied **per column**.

Therefore, do not expect one SPSS variable for the entire matrix.

#### Multiple Textboxes

A **Multiple Textboxes** question contains multiple individual inputs. Metadata is therefore handled **per sub-item**, with each sub-item potentially producing its own exported variable.

#### HTML, Image, and Expression

**HTML**, **Image**, and **Expression** elements do not create standalone exported variables according to the current export rules.

They are primarily used to present content, structure the questionnaire, or calculate/display information within the questionnaire.

## Understanding SPSS Format Notation

The SPSS format shown in the metadata provides information about how the value is represented.

For example:

```text
F10.0
```

means:

* **F** → Fixed numeric format
* **10** → Field width
* **0** → Number of decimal places

Similarly:

```text
A255
```

represents a string field with a width of 255.

Date and time formats use dedicated formats such as:

```text
DATE11
DATETIME20
TIME8
```

The exact representation depends on the underlying data type and export configuration.

### Complete Example

Suppose you create the following survey question:

> **How satisfied are you with your recent online shopping experience?**

Respondents answer using a **1–5 rating scale**.

You configure the metadata as follows:

| Property          | Value                  |
| ----------------- | ---------------------- |
| Variable Label    | Customer Satisfaction  |
| Numeric Width     | 10                     |
| Numeric Decimals  | 0                      |
| Numeric Format    | F                      |
| Measurement Level | Ordinal                |
| Data Type         | Numeric                |
| Missing Value     | 98 = Don't Know        |
| Missing Value     | 99 = Refused to Answer |

Because this is a rating-scale question, VoxDash represents it as a numeric ordinal variable.

When exported to SPSS, the variable may appear similar to:

| Variable Name | Variable Label        | Type    | Missing Values                          |
| ------------- | --------------------- | ------- | --------------------------------------- |
| Q5            | Customer Satisfaction | Numeric | 98 = Don't Know, 99 = Refused to Answer |

An analyst can therefore immediately determine:

* What the variable represents
* That the responses are numeric
* That the variable is ordinal
* Which values represent special/missing responses
* How the numeric values are formatted

This reduces the amount of manual preparation required before statistical analysis.

## Metadata and Question Type: Important Considerations

When reviewing Question Metadata, keep the following principles in mind.

### 1. Question type affects the default metadata

VoxDash uses the selected question type to determine the appropriate SPSS representation.

For example:

```text
Radio Button Group → Numeric / Nominal
Rating Scale       → Numeric / Ordinal
Number             → Numeric / Scale
Text               → String / Nominal
Date               → Date / Scale
```

### 2. Input type can change the underlying data type

This is particularly important for **Single-Line Input**.

A Single-Line Input configured as **Text** is fundamentally different from one configured as **Number**, **Date**, or **Date and Time**.

### 3. Containers do not necessarily create variables

Elements such as **Panels**, **Matrices**, and **Multiple Textboxes** can contain multiple response items. Their metadata is therefore handled according to their internal structure rather than as one standalone variable.

### 4. Export metadata is different from respondent-facing configuration

Metadata determines how collected data is represented in the exported dataset. It does not necessarily change the visual appearance or interaction of the questionnaire.

### 5. Missing values should be standardized

If your organization uses standard codes such as `97`, `98`, and `99`, apply them consistently across questionnaires where appropriate.

## Best Practices

Follow these recommendations when configuring Question Metadata:

* Use clear and descriptive **Variable Labels**.
* Keep variable labels consistent with your organization's data dictionary.
* Avoid changing default SPSS formatting unless there is a specific requirement.
* Use appropriate **Measurement Levels** for statistical analysis.
* Verify the **Data Type** before exporting the questionnaire.
* Use consistent **Missing & Special Values** across questionnaires.
* Make sure missing-value codes cannot be confused with valid responses.
* Review numeric **Width** and **Decimals** for numeric questions.
* Use an appropriate **String Width** for text-based variables.
* Remember that the **input type** matters for Single-Line Input questions.
* Review matrix and container questions separately because they may generate multiple variables rather than one.
* Check metadata before exporting to SPSS, especially for questionnaires that will be analyzed by another team.

> **Tip:** If your organization has centralized SPSS metadata standards, configure the administrator defaults first and use question-level overrides only when necessary.

## Summary

The **Question Metadata** panel controls how questionnaire responses are represented in exported statistical datasets. It provides control over **variable labels, SPSS formats, numeric and string settings, measurement levels, data types, and missing-value definitions**.

VoxDash also automatically applies metadata rules based on the selected **question type and input type**. Understanding these rules is particularly important for SPSS exports because the same-looking response control can represent different types of data depending on its configuration.

Correctly configured metadata helps you:

* Produce cleaner SPSS datasets
* Maintain consistent variable definitions
* Reduce manual data preparation
* Correctly distinguish valid and missing responses
* Improve statistical analysis
* Make exported datasets easier for other analysts to understand
* Maintain standardized data structures across projects and questionnaires
