Each question type in **VoxDash** includes its own configuration options that allow you to customize how respondents interact with your questionnaire. These settings help you control answer options, validation rules, appearance, layout, data collection behavior, and conditional logic.

> **Tip:** To configure a question, open the **Designer** tab and click the desired question. The **Question Settings** panel will appear on the right side of the screen.

## General Question Settings

All question types share a common set of settings that control their basic properties and behavior.

### Basic Information

Configure the basic information for the selected question.

#### Question Name

The internal identifier used throughout the questionnaire. The question name is referenced in logic, conditions, exports, and JSON.

#### Question Title

The text displayed to respondents.

**Example**

> What is your preferred payment method?

#### Question Description

Displays additional instructions below the question title.

Use descriptions to provide extra guidance or explain how respondents should answer the question.

**Example**

> Please select the payment method you use most often.

### Text-to-Speech (TTS)

Generate speech for the selected question.

The Text-to-Speech feature allows respondents to listen to questions instead of reading them, improving accessibility and supporting audio-assisted interviews.

For detailed configuration options, see the [Text-to-Speech (TTS)](/Questionnaire-Builder/tts) documentation.

### Layout Settings

These settings control the appearance and layout of the selected question.

#### Display the Question on a New Line

Displays the question on its own row instead of sharing a row with other questions.

#### Question Box State

Controls the default state of the question within the Designer.

Available options:

* **Locked** – Prevents accidental editing.
* **Collapsed** – Shows only the question title.
* **Expanded** – Displays the complete question and its settings.

#### Question Description Alignment

Controls where the question description appears.

Options:

* Inherit questionnaire setting

#### Error Message Alignment

Controls where validation messages are displayed.

Options:

* Inherit
* Top
* Bottom

#### Increase Inner Indent

Adds additional indentation to visually group related questions.

#### Inline Question Width

Specifies the width of the question when displayed alongside other questions.

#### Minimum Question Width

Sets the minimum width before the question automatically wraps to a new line.

#### Maximum Question Width

Limits the maximum width of the question.

#### Column Count

Displays answer choices across multiple columns instead of a single vertical list.

## Conditions

Conditional logic allows questions to appear, become required, or automatically receive values based on respondents' previous answers.

Click the **Magic Wand** icon to create or edit conditional expressions.

### Make the Question Visible If

Displays the question only when the specified condition evaluates to **True**.

**Example**

Show the question **"What is your vehicle model?"** only if the respondent answered **Yes** to **"Do you own a vehicle?"**

### Disable Read-only Mode If

Keeps the question read-only until a specified condition is met.

### Make the Question Required If

Makes the question mandatory only when the specified condition is true.

**Example**

Require the **Employer Name** question only if **Employment Status = Employed**.

### Default Value Expression

Automatically assigns a default value using an expression.

Expressions can include:

* Mathematical calculations
* Boolean comparisons
* Built-in functions

Examples:

```
{price} * {quantity}
```

```
today()
```

```
iif({age} >= 18, "Adult", "Minor")
```

Respondents can still change the value unless the question is read-only.

### Reset Value If

Automatically resets the question value when the specified condition is met.

The question will return to its **Default Answer** or **Default Value Expression**.

### Set Value If

Specifies when VoxDash should automatically calculate and assign a value.

### Set Value Expression

Defines the value assigned when the **Set Value If** condition is satisfied.

Expressions support calculations, functions, and references to other questions.

### Hide the Question If It Has No Choices

Automatically hides the question if no answer choices are available.

This is useful when choices are generated dynamically.

### Make Choices Visible If

Shows or hides answer choices based on conditions.

**Example**

Display the option **Electric Vehicle** only if the respondent selected **Owns a Car**.

### Make Choices Selectable If

Keeps answer choices visible but disables them until the specified condition is met.

Unlike **Make Choices Visible If**, the choices remain visible but cannot be selected.

## Data Settings

These settings control how responses are stored and exported.

### Join Identifier

A **Join Identifier** links multiple questions together using a shared key.

Their responses are grouped into a single object or array in the exported dataset.

**Example**

Questions:

* Street
* City
* Postal Code

Join Identifier:

```
address
```

Exported result:

```json
{
  "address": {
    "street": "12 Main Street",
    "city": "London",
    "postalCode": "SW1A 1AA"
  }
}
```

### Default Answer

Defines the answer automatically assigned when the questionnaire first loads.

### Correct Answer

Defines the correct response for quizzes or scored questionnaires.

### Use Display Values in Dynamic Texts

Displays the visible answer text instead of the internal choice value in HTML elements and dynamic text.

### Default Display Value for Dynamic Texts

Specifies the placeholder text displayed when the question has not yet been answered.

### Clear Hidden Question Values

Determines whether answers should be cleared when a question becomes hidden by conditional logic.

Options include:

* Inherit questionnaire setting
* Never
* Upon questionnaire completion
* When the question becomes hidden

## Question-Specific Settings

### Radio Button

The **Radio Button** question allows respondents to select **one** option from a list.

#### Available Settings

* Add, edit, or delete answer choices.
* Copy choices from another question.
* Change the order of answer choices.
* Show the **Clear** button.
* Separate special choices such as **Other** and **None**.
* Enable the **Other** option.
* Enable the **None** option.
* Apply visibility conditions to individual choices.

**Example**

**Question**

What is your preferred payment method?

Choices:

* Credit Card
* PayPal
* Bank Transfer
* Other

If **Other** is selected, respondents can enter a custom answer.

### Dynamic Matrix

Each column in a Dynamic Matrix has its own configuration options that control how data is collected, displayed, and validated. This allows you to create tables where each column behaves differently. For example, one column can accept text, another can accept numbers, while another displays a dropdown list.

To edit a column, select the Dynamic Matrix question, then click the column you want to configure. The Column Settings panel will appear on the right side of the screen.

#### General Column Settings

**Column Name:** The internal identifier used for the column.
This name is used in:

Logic expressions
Conditions
JSON exports
Data exports

**Column Title:** The text displayed as the column header to respondents.

**Cell Input Type:** Choose the type of input displayed in each cell of the column.

Available input types include:

* Text
* Number
* Dropdown
* Checkbox
* Date
* Rating
* Email
* Phone Number
* URL
And other supported question input types

**Visible:** Determines whether the column is displayed to respondents.
Disable this option if the column should be hidden while still being used internally.

**Read-only:** Prevents respondents from editing values in the column.
This is useful for calculated or automatically populated values.

**Required:** Makes the column mandatory.
Respondents cannot submit the questionnaire until every required cell in the column has been completed.

**Prevent Duplicate Responses:** Prevents respondents from entering duplicate values within the same column.

**Column Width:** Specifies the width of the column.
Increase the width for columns that contain longer values.

**Minimum Column Width:** Defines the minimum width before the column automatically resizes.

#### Column Conditions

Like questions, each column supports conditional logic. Click the Magic Wand icon to create or edit expressions.

**Make the Column Visible If:** Displays the column only when the specified condition is met.

**Disable Read-only Mode If:** Makes a read-only column editable when a condition becomes true.

**Make the Column Required If:** Makes the column mandatory only when the specified condition is satisfied.

**Default Value Expression:** Automatically assigns a default value using an expression.

Supported expressions include:

Mathematical calculations
Boolean logic
Built-in functions

Examples:

today()
{quantity} * {price}
iif({age} >= 18, "Adult", "Minor")
Reset Value If

Automatically clears or resets the cell value when a specified condition is met.

**Set Value If:** Defines when VoxDash should automatically assign a calculated value.

**Set Value Expression:** Defines the value assigned when the Set Value If condition is true.

Example

{unit_price} * {quantity}

The calculated value can still be edited unless the column is configured as Read-only.

#### Column Totals

The Totals section allows you to calculate summary values for numeric columns.

**Aggregation Method:** Choose how values in the column are summarized.

Available options include:

* None
* Sum
* Average
* Minimum
* Maximum
* Count

(Available options may vary depending on the selected column type.)

**Total Value Expression:** Instead of using a standard aggregation, you can calculate totals using a custom expression.

Expressions support:

* Mathematical calculations
* Boolean logic
* Built-in functions
This is useful when calculating totals such as overall cost, weighted scores, or custom metrics.

#### Column Validation

Validation rules help ensure that respondents enter valid and consistent data.
Depending on the selected Cell Input Type, you can configure validation options such as:

* Required values
* Minimum and maximum values
* Minimum and maximum text length
* Valid email format
* Valid URL format
* Regular expression (pattern) validation
* Custom validation rules
* Custom validation messages

This question type is ideal for collecting repeating information, such as lists of purchased products, household members, or previous employers.

## Summary

VoxDash provides a wide range of question types and configuration options to support simple and complex questionnaires. By combining question settings, conditional logic, validation rules, and data configuration, you can create dynamic surveys that are easy for respondents to complete and generate high-quality, structured data for analysis.

As a best practice, always preview and test your questionnaire after making changes to ensure that questions, logic, and validation rules behave as expected before publishing.
